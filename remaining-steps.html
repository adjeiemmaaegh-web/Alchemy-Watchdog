Scope

This is an owner planning page, not a live task board or proof that tests have passed. Publishing it does not install or deploy Watchdog.

01

01. Finish the Watchdog engineering evidence

Engineering owns the implementation. You approve the evidence, not only the test count.

01
Engineering

Packaged executable: camera to reviewed incident

Run the real installed Windows executable with an authorized camera or replay, identify an event, save a timestamped playable clip and complete the human incident review workflow.

Done whenA packaged-app test report with exact installer hash, footage source, screenshots, playable evidence and reviewer decision.
02
Engineering

Real Qwen model, not a fallback summary

Run the bundled llama.cpp/GGUF inference path with actual structured CCTV and POS events, while video processing continues on a low-resource CPU.

Done whenLogs and examples that show grounded outputs, safe timeouts/fallbacks, and CPU/RAM impact without unsupported accusations.
03
Engineering

One-command clean installer packaging

Produce a self-contained installer from a clean checkout. Bundle the legally permitted YOLO weights, FFmpeg, local AI model and runtime; never require users to install Python or download model weights.

Done whenA repeatable build command, manifest, hashes, complete asset inventory and clean-machine install.
04
Engineering + Owner

Measure detection accuracy and false alerts

Test representative, consented retail clips with ground-truth labels, lighting and camera variation, ordinary transactions and difficult edge cases.

Done whenDocument precision, recall, missed cases, false-alert rate and human adjudication; no detector alone establishes theft.
05
Engineering

Prove POS/CSV reconciliation and security

Verify offline transaction imports, mismatches, refunds, discounts, duplicates, incident links, access control, safe logging, evidence integrity, backup/restore and crash recovery.

Done whenReproducible pass/fail scenarios with verified per-shop isolation, correct incident history and recoverable user data.
02

02. Complete physical shop and device acceptance

Real equipment and shop observation are your responsibility. Development should continue while these checks remain pending.

01
Owner

Test USB/IP/RTSP cameras in one shop

Connect authorized cameras at a real shop; check startup, reconnect after outages, timestamping, clip retention, permissions, and incident playback.

Done whenRecord camera make/model, observed interruptions and an end-to-end reviewed sample incident.
02
Owner

Benchmark a genuine 8 GB Windows 11 PC

Run video capture, local detection, incident UI and optional Qwen on the intended low-spec computer with no dedicated GPU for a representative shift.

Done whenRecord sustained CPU/RAM/disk consumption, frame throughput, latency, stability and usable operating limits.
03
Owner + Engineering

Practice install, upgrade, rollback and recovery

Test clean install, repair, uninstall, permissions, restart, corrupted data and restoring evidence. Perform the C → C.1 → C.2 → C.1 installer rollback drill on test hardware.

Done whenAn auditable recovery log proves no unexpected footage or incident loss.
04
Owner

Run an ethical single-shop pilot

Choose a consented pilot site, train reviewers, review false positives, collect operational feedback and ensure no automated allegation is treated as a verdict.

Done whenPilot observations, defects, response procedures, human sign-off and a clear decision on further distribution.
03

03. Clear website, legal and commercial gates

Publishing this informational page is separate from pilot distribution or commercial approval.

01
Owner + Legal + Engineering

Resolve model, AGPL and FFmpeg obligations

Review exact YOLO/AGPL requirements, model provenance, FFmpeg LGPL/GPL configuration, source/build redistribution terms and any needed commercial licence.

Done whenLegal sign-off, matching source/licence notices and distribution documentation for the exact released binaries.
02
Owner + Legal

Approve surveillance privacy and access rules

Document applicable CCTV/employee notices, permitted purpose, retention, authorized access, deletion, audit trails and incident escalation.

Done whenA reviewed, locally applicable policy used in the pilot and user training.
03
Owner

Finish the Alchemy website's real contact and legal copy

Approve an official inbox in place of the inactive hello@alchemy.example placeholder, update draft privacy/terms and review every product claim or illustration.

Done whenVerified contact path, approved wording and no false claim that the site stores registrations or proves AI accuracy.
04
Owner + Web QA

Approve domain, HTTPS and accessibility

Choose the canonical domain; validate TLS, mobile/desktop links, SEO, responsive widths, real Firefox/Safari/mobile devices and keyboard/screen-reader use.

Done whenDocumented live-host check and accessibility/compatibility sign-off.
05
Owner

Authorize pilot and commercial release separately

Review release criteria, hardware support, security, licensing, QA defects, price/ROI evidence and allowed rollout audience before any customer-facing release.

Done whenA dated go/no-go decision identifying the exact tested installer and permitted scope.
04

04. Complete the related Tallybook Telegram bot setup

This is a separate Alchemy product workstream, not a Watchdog single-shop blocker. The GitHub PR, migration and Edge Function were completed on 12 November 2026.

01
Owner

Create the dedicated bot with @BotFather

In Telegram, message @BotFather, use /newbot and choose a username ending with bot. Keep the HTTP API token secret.

Done whenPrivate token stored safely; never published in GitHub, this website or a client .env.
02
Owner

Configure the two secret values in Supabase

Set TELEGRAM_BOT_TOKEN and a newly generated TELEGRAM_WEBHOOK_SECRET in Edge Function secrets. The platform provides SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY.

Done whenFunction environment configured without committing any credentials.
03
Owner

Register and verify Telegram setWebhook

Use the deployed tallybook-telegram endpoint with the exact same secret_token; inspect getWebhookInfo and confirm unauthorized requests are rejected.

Done whenTelegram reports the correct endpoint and no delivery errors.
04
Owner + QA

Publish the Tallybook frontend and run /today

Confirm production web deployment includes the merged PR #72; optionally set VITE_TALLYBOOK_TELEGRAM_BOT to the public username. In Team, mint a link code, open the deep link, then test /today, /settings and /stop privately.

Done whenThe correct shop's sales and capabilities return from the real bot. This end-to-end test is still unverified.
05

05. Future development — not Phase 1 acceptance blockers

Keep these on the roadmap without presenting them as finished or stopping the current one-shop build.

01
Later stage

Secure multi-store owner oversight

Build authorized remote store agents, offline queues, secure synchronization, tenant-isolated overviews and central incident management.

Done whenSeparate release and cross-shop security verification.
02
Later stage

Live Watchdog–Tallybook integration and advanced tiers

Implement tested live synchronization and Professional/Enterprise capabilities only after stable single-shop workflows, licensing and operating requirements.

Done whenA separately accepted integration with scoped data-sharing and commercial approvals.
THE GO / NO-GO GATE

Three different approvals.

Website publication simply publishes information. A single-shop pilot needs the hardware, security, data and human-review evidence above. Commercial distribution requires additional legal, licensing and release approval. Do not treat them as the same event.
